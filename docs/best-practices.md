# Remotion ベストプラクティス

## コアの考え方

- **`useCurrentFrame()` が全て**: アニメーションは CSS トランジションや `useEffect` ではなく、フレーム番号から値を導出する。同じフレームなら常に同じ見た目になる純粋関数として書く。
- **`interpolate()` / `spring()` を使う**: 手動でイージングを書くより、組み込みのこの2つを使うと自然で調整しやすい。
- **ランダム性・現在時刻は禁止**: `Math.random()` や `Date.now()` を直接使うとレンダリング時とプレビュー時で結果が変わる。`random(seed)` のようなシード付き関数を使う。

## 構成・シーン管理

- **`<Sequence>` でタイミングを分割**: `from` / `durationInFrames` でシーンの出現タイミングを管理し、各シーン内部は0起点のローカルフレームで考える。
- **`<Series>` / `<TransitionSeries>`**: 複数シーンを連結する場合はこれらのヘルパーを使うと管理が楽。
- **Composition は小さく合成可能に**: 1つの巨大なコンポーネントに全部書かず、シーンごとにコンポーネント分割する。

## Props・型

- **Zod スキーマで props 定義**: `defaultProps` と一緒に Zod スキーマを使うと、Studio 上で GUI から値を編集できるようになる。

## アセット

- **`staticFile()` を使う**: public フォルダの画像・音声などは直接パス文字列でなく `staticFile()` 経由で参照する。
- **画像・フォントは事前読み込み**: `<Img>` コンポーネントやフォント読み込みユーティリティを使い、レンダリング時のちらつきや読み込み漏れを防ぐ。

## パフォーマンス

- 重い計算はコンポーネント外や `useMemo` でキャッシュする。
- レンダリング時に不要なネットワークリクエストを避ける（決定論的でないと並列レンダリングで結果がズレる）。
